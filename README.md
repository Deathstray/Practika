# Система диспетчеризации служебного транспорта

Веб-приложение для управления служебным транспортом предприятия. Реализует все 5 этапов технического задания.

## Стек технологий

- **Фронтенд**: Nuxt 3 (Vue 3) + Tailwind CSS + ECharts
- **Бэкенд**: FastAPI (Python 3.11)
- **База данных**: PostgreSQL 16
- **Авторизация**: JWT-токены
- **Деплой**: Docker + Docker Compose

## Быстрый старт

### Требования

- [Docker](https://www.docker.com/get-started) версии 20+
- [Docker Compose](https://docs.docker.com/compose/install/) v2+

### Запуск

```bash
# 1. Склонировать/распаковать проект
cd transport-system

# 2. Запустить все сервисы
docker compose up --build

# Ждать ~2-3 минуты пока соберётся фронтенд
```

После запуска:
- **Фронтенд**: http://localhost:3000
- **Бэкенд API**: http://localhost:8000
- **Документация API (Swagger)**: http://localhost:8000/docs

### Остановка

```bash
docker compose down
```

Для полного сброса (включая БД):
```bash
docker compose down -v
```

## Демо-аккаунты

Все аккаунты имеют пароль: **`admin123`**

| Логин | Роль | Описание |
|-------|------|----------|
| `dispatcher` | Диспетчер | Управление заявками, назначение водителей, статистика |

## Функциональность по этапам

### Этап 1 — Фундамент ✅
- Nuxt 3 + FastAPI + PostgreSQL, запуск через Docker Compose
- Схема БД с миграциями через SQLAlchemy + init.sql
- Регистрация и вход с JWT-токеном
- Разграничение по ролям (сотрудник / диспетчер / водитель)
- CRUD для водителей и автомобилей

### Этап 2 — Заявки ✅
- Форма создания заявки с полями: откуда, куда, дата/время, цель, примечания
- Список заявок сотрудника с текущими статусами
- Очередь заявок диспетчера с фильтрацией по статусу и дате
- Принятие / отклонение заявок с указанием причины

### Этап 3 — Полный цикл поездки ✅
- Назначение водителя и автомобиля на принятую заявку
- Проверка занятости водителя и машины в пересекающееся время
- Отметка водителем факта выезда и возвращения
- Сотрудник может отменить заявку в статусе «новая»

### Этап 4 — История и управление ✅
- История поездок диспетчера с фильтрами (дата, водитель, статус)
- История заявок для сотрудника
- Справочник часто используемых адресов с автодополнением
- Экспорт истории в Excel

### Этап 5 — Дашборд и аналитика ✅
- Дашборд: активные поездки, свободные водители, новые заявки
- Статистика за период: топ маршрутов, загруженность водителей
- Графики (ECharts): динамика заявок по дням, загруженность водителей

## API Endpoints

### Авторизация
| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/auth/login` | Вход |
| POST | `/auth/register` | Регистрация |
| GET | `/auth/me` | Текущий пользователь |

### Заявки
| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| POST | `/orders/` | employee | Создать заявку |
| GET | `/orders/my` | employee | Мои заявки |
| DELETE | `/orders/{id}/cancel` | employee | Отменить заявку |
| GET | `/orders/` | dispatcher | Все заявки (с фильтрами) |
| POST | `/orders/{id}/accept` | dispatcher | Принять |
| POST | `/orders/{id}/reject` | dispatcher | Отклонить |
| POST | `/orders/{id}/assign` | dispatcher | Назначить водителя/машину |
| GET | `/orders/driver/assignments` | driver | Назначенные поездки |
| POST | `/orders/{id}/depart` | driver | Отметить выезд |
| POST | `/orders/{id}/return` | driver | Отметить возврат |
| GET | `/orders/export/excel` | dispatcher | Экспорт в Excel |

### Справочники
| Метод | Путь | Описание |
|-------|------|----------|
| GET/POST/PATCH/DELETE | `/drivers/` | Водители |
| GET/POST/PATCH/DELETE | `/vehicles/` | Автомобили |
| GET/POST/PATCH/DELETE | `/addresses/` | Адреса |

### Статистика
| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/stats/dashboard` | Данные дашборда |
| GET | `/stats/` | Статистика за период |

## Схема базы данных

Файл `init.sql` содержит полную схему БД:
- `roles` — справочник ролей
- `users` — пользователи с привязкой к роли
- `drivers` — водители
- `vehicles` — транспортные средства
- `orders` — заявки на транспорт
- `order_status_history` — история изменения статусов
- `common_addresses` — часто используемые адреса

Все таблицы имеют индексы и ограничения целостности.
